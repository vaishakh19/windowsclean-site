**DockerとWSLの容量には、Linux内部のデータと、Windowsに保存された仮想ディスクという2つの層があります。** 不要なイメージやLinuxファイルを消しても、C:の空きがすぐ増えるとは限りません。VHDX自体を削除すると、環境を失うおそれがあります。

まず読み取りだけで測定します。Docker、個人用WSLディストリビューション、通常のWindowsファイルのどれが増えているか確認しましょう。場所が不明なら、[大きなファイルを探し](/articles/find-large-files-windows/)、完全なパスを記録してから操作を選びます。

## どの環境のデータかを確認する

PowerShellで一覧を表示します。

```powershell
wsl --list --verbose
```

インストール済みのディストリビューションとWSLの版が分かります。WSL 2は仮想ディスクを使いますが、WSL 1は別の構造です。Docker Desktopも、バックエンド、バージョン、以前のインストール状態によって保存方式が変わります。どのPCにも`docker-desktop-data`があるとは想定しないでください。

[MicrosoftのWSL容量ガイド](https://learn.microsoft.com/en-us/windows/wsl/vhd-size)には仮想容量とVHDXの場所の確認方法があり、[DockerのWindows向け説明](https://docs.docker.com/desktop/features/wsl/)にはWSLとの関係が記載されています。古い掲示板のパスではなく、自分の構成に対応する説明を使います。

## Dockerの内訳を先に調べる

Docker Desktopを起動した状態で、次を実行します。

```powershell
docker system df
docker system df -v
docker container ls -a
docker image ls
docker volume ls
```

これらは確認用のコマンドです。[Dockerのディスク使用量リファレンス](https://docs.docker.com/reference/cli/docker/system/df/)を参考に、イメージ、停止中コンテナー、ビルドキャッシュ、ボリュームを区別します。「回収可能」という技術的な分類は、あなたにとって不要という意味ではありません。

停止中のデータベースコンテナーでも、後で再開する仕事に使うかもしれません。接続先のないボリュームが、開発用データベースの唯一のコピーという場合もあります。各資源のプロジェクトを特定し、永続データをバックアップしてから削除を判断してください。

## 広範囲なpruneより対象を絞る

用途が分かる古いイメージや不要な停止中コンテナーは、Docker Desktopで詳細を確認し、対象だけを削除する方法を優先します。タグも参照元もないイメージには、次のコマンドがあります。

```powershell
docker image prune
```

これは削除を行うコマンドです。確認画面を読み、範囲が分からなければ中止します。すべての未使用イメージを消すより限定的でも、必要になったとき再構築や再取得ができるか考えてください。

より広い`docker system prune`は、停止中コンテナー、未使用ネットワーク、未使用ビルドキャッシュなども対象にします。説明なしの容量対策として実行しないでください。`--all`や`--volumes`は範囲をさらに広げます。[Dockerのpruneガイド](https://docs.docker.com/engine/manage-resources/pruning/)を読み、確認プロンプトを省略しないようにします。

## 個人用WSLは別に確認する

普段使っているディストリビューションを開き、次を実行します。

```bash
df -h /
du -h --max-depth=1 ~ 2>/dev/null
```

最初はファイルシステムの使用量、次はホームディレクトリの内訳です。2つ目はLinux全体を調べるものではありません。古いビルド成果物、データセット、依存関係のキャッシュなどを見つける出発点になります。ホーム以外の大きなデータは別途確認します。

用途の分かるものだけを、可能ならアプリやパッケージ管理ツールで整理します。Linuxのシェルで削除した内容は、通常Windowsのごみ箱には入りません。`wsl --unregister`は容量整理の近道ではなく、ディストリビューションとデータを削除する操作です。

## VHDXが小さくならない理由

動的に拡張する仮想ディスクは、内部のファイルを削除した後もホスト上の割り当てを保持する場合があります。最大容量、Linuxの使用量、Windows側の物理的な保存量は別の数値です。仮想容量が大きいからといって、そのすべてをSSDで消費しているとは限りません。

整理後はWindowsの空き容量と内部の測定を比較します。ホスト側が不足したままなら、そのバックエンドの最新の回収・圧縮手順を調べます。仮想ディスクの縮小は別の保守作業であり、ファイルを削除や改名してよい理由にはなりません。

保守前には作業を保存し、大切なデータをバックアップして、関連する処理を完全に止めます。`wsl --shutdown`は動作中のWSL環境を停止させるため、実行中の仕事があるときは使わないでください。推測したVHDパスを対象にする圧縮コマンドも避けます。

## 今後の増加を管理する

プロジェクト、永続ボリューム、再生成できる成果物を簡単に記録します。共有資源を消す前に、古いプロジェクトがまだ必要か確認してください。大きなドライブへ移すときも、エクスプローラーでディスクをドラッグせず、対応するインポート、エクスポート、アプリ設定を使います。

通常のWindowsデータは[AppDataの容量](/articles/appdata-folder-too-big/)や[別ドライブへの移動](/articles/move-files-to-another-drive-windows/)を参照してください。Windows Cleanは、アクセス可能なホスト側の大きなファイルを無料・オフライン・アカウント不要・管理者権限不要で調べられます。VHDX内のLinuxを解析したりDockerを圧縮したりする機能ではありません。

## よくある質問

### ext4.vhdxを削除すればよいですか？

ディストリビューションを残したいなら削除しません。Linuxのファイルシステムが入っています。所有する環境を特定し、バックアップ後に正式な整理や削除を行います。

### docker system dfは減ったのにC:が空かないのはなぜですか？

内部使用量とホスト上の割り当てが異なるためです。仮想ディスクが割り当てを保持し、バックエンド固有の回収処理が必要な場合があります。

### 未使用ボリュームなら消して大丈夫ですか？

自動的に安全とは言えません。停止・削除済みプロジェクトの永続データが残っている可能性があります。内容と用途を確認し、必要なものを保存してください。
